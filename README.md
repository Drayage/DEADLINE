# DEADLINE — 라인 전략 RTS

3라인(상/중/하) 턴제 전략 게임. 경제(일꾼) · 러쉬(유닛) · 방어(포탑) · 정보(정찰)의
심리전으로 상대 본진을 파괴한다. **생산물은 항상 한 턴 늦게 반영**되어, 공격을 보고
급하게 막을 수 없는 것이 핵심.

## 실행

- **게임 플레이(vs AI)**: 브라우저로 `index.html` 열기 (별도 설치 없음, **엔진이 인라인된
  자체완결 단일 파일** — 다른 파일 없이도 동작).
- **온라인 대전(방 코드)**: 아래 "온라인 대전" 참고. 정적 호스팅(GitHub Pages)만으로 동작.
- **밸런스 테스트(콘솔)**: `node sim.js` — 전투 단위 테스트 + 락스텝 결정성 테스트 + AI vs AI
  매치업 승률.
- 게임 화면 우측 "밸런스 테스트" 패널에서도 매치업/전체표 실행 가능.

## 온라인 대전 (방 코드)

내 서버 없이 **Firebase Realtime Database를 "우편함(중계)"** 으로만 쓰는
**클라이언트-권위 락스텝(lockstep)** 방식. 두 클라가 같은 결정적 엔진을 돌리고, 매 턴
**자기 행동 목록만** 교환해 양측이 동일하게 해결한다(→ 동일 상태). GitHub Pages 같은 정적
호스팅으로 충분.

- 플레이: 헤더 **🌐 온라인 대전** → **방 만들기**(코드 공유) 또는 **참가**(코드 입력).
  양쪽이 입장하면 시작. 각자 본진이 항상 왼쪽으로 보인다.
- 한계: 릴레이라 각 클라가 전체 상태를 가짐 → **친구 간 캐주얼 대전용**(완전한 치팅 방지는
  권위 서버가 필요).

### 설정 (1회)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트 생성 → **Realtime
   Database** 활성화.
2. **규칙**을 방 단위 읽기/쓰기로 설정:
   ```json
   { "rules": { "rooms": { "$code": { ".read": true, ".write": true } } } }
   ```
3. 웹 앱 등록 후 발급되는 config를 `index.template.html`의 `FIREBASE_CONFIG`에 넣고
   `node build.js`로 재빌드. (웹 apiKey는 공개돼도 정상 — 보안은 위 DB 규칙으로.)
4. GitHub Pages 활성화(레포 Settings → Pages → 루트). 푸시하면 배포된다.

## PWA (설치 / 오프라인 싱글플레이)

`manifest.json` + `sw.js`(서비스워커)로 **설치 가능**하며, 앱 셸을 캐시해 **싱글플레이는
오프라인**에서도 동작한다(온라인 대전은 네트워크 필요). `index.html`을 갱신하면 `sw.js`의
`CACHE` 버전을 올린다.

## 파일

- `engine.js` — 순수 게임 로직 + AI(5성향) + 시뮬레이터. 브라우저·Node 공용(DOM 무의존).
  **게임 로직의 단일 소스.**
- `index.template.html` — UI(HTML/CSS + 프런트 스크립트). `/*__ENGINE_INLINE__*/` 자리에
  엔진이 주입된다.
- `index.html` — **생성물**. `node build.js`가 템플릿 + 엔진을 합쳐 만든 자체완결 단일 파일.
- `build.js` — `engine.js`를 `index.template.html`에 인라인해 `index.html` 생성.
- `sim.js` — Node용 밸런스 테스트 + 락스텝 결정성 테스트 러너.
- `manifest.json` · `sw.js` · `icon.svg` · `icon-maskable.svg` — PWA(설치/오프라인) 자산.

> 엔진이나 템플릿을 고치면 `node build.js`로 `index.html`을 다시 생성한다.

## 규칙 요약

- 시작: 골드 100 / 일꾼 5 / 본진 HP 30. 턴당 **행동 2회**.
- 비용: 일꾼 50, 유닛 50, 포탑 100, 본진포탑 100, 연구 100. 일꾼 1명당 턴당 +10골드.
- **유닛/포탑/본진포탑은 행동 1회당 1~3개** 선택 생산(개당 비용). 포탑/본진포탑은 **여러 개
  중첩**(스택) 가능 — 유효 포탑 수 = ceil(hp/20), 공격·회복도 포탑 수만큼 스케일.
- **연구**(각 100G, 무제한, 턴 종료 완성): 공격연구 = 유닛 ATK +2/레벨, 방어연구 = 유닛 HP +
  정찰병 HP +2/레벨.
- **교차 전투**: 두 진군 병력이 인접 칸에서 마주보고 스쳐 지나갈 상황이면 이동 전에 먼저
  전투(전멸까지)하고 이긴 쪽만 한 칸 전진.
- **맵**: 라인당 5칸 `[내 본진][내 1칸][중앙][적 1칸][적 본진]`. 유닛은 내 1칸에서 생성,
  적 본진까지 3칸(3턴) 진군. 공격 시 **보낼 수량 선택**.
- **전투**: 같은 칸에서 만나면 한쪽이 전멸할 때까지 즉시 동시교전. 이동은 턴당 1칸.
  유닛 HP10/ATK10, 포탑 HP20/ATK20(턴 종료 시 +2 회복). → **순차 공격 < 모아치기**.
  - 1기 vs 포탑 = 포탑 승 / 2기 동시 = 동귀어진 / 3기 동시 = 포탑 파괴 후 침투.
- **본진**: 본진포탑 → 일꾼 → 본진 순으로 공격. 본진 HP 0이면 패배. 본진포탑 재건 가능.
- **정찰**: 일꾼 1명이 정찰병(HP15)으로 라인 통과. 공격은 안 하고 맞기만 함. 살아남은 칸은
  정확한 적 병력/포탑 공개, 죽으면 사망 위치만. 적 본진 도달 시 정보 전부 획득(본진포탑
  있으면 일꾼 사망, 없으면 무사 귀환).
- **전장의 안개**: 적 정보는 비공개. 어떤 칸의 적 병력/포탑은 **그 칸에 내 유닛 또는 내
  포탑이 있을 때만** 보인다(없으면 내 1칸이라도 안개). 적 본진 HP/본진포탑은 내 병력이
  적 본진에 닿거나 정찰로 도달해야 공개. 정찰 정보는 우측 패널에 누적된다.
- **연출**: 본진은 좌우 단일 블록(3라인이 한 본진으로 수렴). 턴 종료 후 이동→전투→수입→
  생산→정찰이 단계별 애니메이션으로 재생되고, 교전 시 교전 화면(나 vs 적, 결과)이 뜬다.

## 턴 처리 순서

행동 → 이동 → 전투 → 수입 → 생산 완료 → 정찰 결과 공개. (생산은 이번 턴 전투 불참.)

## AI 성향 (밸런스 테스트용)

`rush`(극한러쉬) · `turtle`(1포탑배째기) · `economy`(무한경제) · `timing`(타이밍러쉬) ·
`scout`(정찰형). 게임에서 AI 성향은 랜덤으로 부여되며 패배/승리 시 공개.

## 밸런스 현황 (튜닝 진행 중)

- ✅ 전투 수학은 기획안 포탑 밸런스 예시와 정확히 일치(단위 테스트 통과).
- ✅ "무지성 러쉬는 막힌다" — 방어형이 극한러쉬를 안정적으로 제압.
- ⚠️ 현재 방어 우위가 강해 방어형끼리는 무승부(턴 상한)가 잦음. 공격 강화/일꾼 데미지소화
  완화 등은 함께 튜닝 예정.
